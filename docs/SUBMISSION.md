## Фиксация сдаваемой версии

В форму сдачи необходимо вставить **полный SHA опубликованного финального коммита**, а не только `dev`.
Коммиты после дедлайна по слайду не учитываются. SHA проверяется на GitHub после публикации:

```bash
git status --short
git rev-parse HEAD
git ls-remote origin refs/heads/dev
```

Для проверки той же версии эксперт может выполнить `git checkout <полный_SHA>`, затем шаги README.
Существующий `v1.0.0` указывает на `cf83a5632cd605dfd21f1494b5fafd96846e3a7e` и **не содержит последних
исправлений**. Его нельзя выдавать за текущий комплект. Менять старый тег для сдачи не требуется: полного
опубликованного SHA достаточно по условиям.

На момент аудита опубликованная `dev` указывает на `86a1f72f36f89c8caea40b8c86b5f6d15f563e0d`.
Проверенная реализация с исправлениями интеграции - `0bd8844f1eeeacc450ce6be3ca7ab00ee2124de3`;
она подготовлена локально. Перед сдачей нужно опубликовать изменения и зафиксировать финальный SHA
с учётом последующих правок документации. Статус публикации не подтверждается одним наличием локального коммита.

## Доступ и демонстрация

GitHub API при аудите подтвердил, что репозиторий публичный. Условие отдельного доступа аккаунту
`alfa-hack-2026` применяется, если репозиторий станет приватным; тогда доступ нужно проверить до сдачи.

Адрес стенда: [dev.alpha.leksika1.ru](https://dev.alpha.leksika1.ru). При аудите страница,
`/api/v1/openapi.json` и вход `demo` ответили HTTP 200. Учётка видит три компании; API вернул разные ленты
для `U_700001` и `U_700002` (20 и 12 карточек). В открытых карточках есть источники и объяснения персонализации.
Платная LLM и полный сценарий через браузер в этом аудите не проверялись. До демонстрации пройти:

1. Вход `demo` / `demo12345`, переключение компании: металлоторговля → розница → логистика.
2. Разница подборок и объяснение «почему важно» через реальные признаки выбранной компании.
3. Полная новость, источник, страница PDF и трасса; информация в карточке должна быть проверяемой.
4. Вопрос к карточке с завершением `done` или понятной ошибкой.
5. Заявка на звонок, история заявки, отзыв и изменение профиля.

Нужен интерактивный работающий прототип. Скриншоты и заранее подготовленные экраны сами по себе
не заменяют этот сценарий. Внешний стенд на слайде рекомендован дополнительно; основной обязательный
комплект должен позволять самостоятельный запуск.
