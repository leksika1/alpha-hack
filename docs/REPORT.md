# Отчёт о решении: бэкенд «Альфа-Будущее»

Сервис персональных бизнес-инсайтов для «Альфа-Бизнеса». Бэкенд собирает и проверяет данные, даёт ML-агенту
инструменты и доступ к LLM, проверяет результат, доставляет инсайты в интерфейс и измеряет качество.

## Что реализовано

| Блок | Результат | Где |
|---|---|---|
| Данные компаний | Загрузка CSV организаторов: 85 513 компаний, 1,4 млн платежей за ~2 мин; отчёт качества; граф связей (платежи, общие физлица, гипотезы с уверенностью); контекст компании — признаки с источником и полнотой. Недостающее — `NULL`, данные не выдумываются | ADR-015–017, `docs/DATA.md` |
| Новости | 41 проверенный источник: RSS российских и зарубежных изданий, отраслевые рубрики, страницы новостей Минтранса, Минсельхоза, Минэкономразвития и ФНС без RSS. Вежливый сбор (robots.txt, User-Agent, лимиты), сырьё в S3, дедупликация, склейка в события (одно событие на решение Банка России), срочность, защита от prompt injection, отсев онлайн-трансляций. Недоступный источник пропускается, есть резервные. Тегер понимает русский и английский | ADR-020–022, 036, 039, 040, 044, `docs/SOURCES.md` |
| Источники под управлением админа | Поиск издания по названию или ссылке на сайт, проверка ленты, добавление без деплоя, включение и выключение. Сборщик ходит только в публичный интернет | ADR-036 |
| Новость от пользователя | Ссылка или текст обрабатываются общим конвейером; инсайт — только для компании пользователя; недоступный ресурс — понятное сообщение | ADR-038 |
| Аналитика банка | PDF → текстовый слой или OCR (Tesseract) → фрагменты со страницами → эмбеддинги и полнотекстовый индекс → гибридный поиск. Ссылка на страницу PDF через API. Загрузка PDF из админки | ADR-023–027, 033, FR-A7 |
| Инфраструктура агента | Tools API (run-токен, только своя компания, аудит вызовов), LLM Gateway, генерация через очередь, валидатор инсайтов и ответов, трассировка каждого шага | ADR-019, 028 |
| LLM Gateway | Белый список из 6 моделей кейса, дневной бюджет с резервированием (держится и при параллельных вызовах), доля бюджета на вопросы, маскирование персональных данных, кэш, журнал расхода с кодами ошибок, прокси для недоступного провайдера | ADR-028, 035, 041 |
| Соответствие законодательству РФ | Новости с дискредитацией ВС РФ и сайты из реестров не попадают к пользователям; инсайты и ответы проверяются на дискредитацию, призывы к санкциям и экстремизму | ADR-037 |
| Матчинг | Предфильтр по индексу и скорер с разбивкой по компонентам; событие по всей базе (~42 тыс. клиентов) — 4,1 с в худшем случае | ADR-029 |
| Доставка по CJM | Лента и виджет на главной, карточка с «почему для вас», трассировка, вопросы к аналитике (SSE), действия (мок-CRM), «наблюдать», отзывы, уведомления (SSE), дайджест. Лента не перегружается одной макротемой | ADR-030, 042, `docs/INTEGRATION_FRONTEND.md` |
| Рыночные данные | Ключевая ставка и официальные курсы ЦБ раз в час: агенту — инструмент `get_market_data`, виджету — `GET /market` | ADR-043 |
| Метрики и эксплуатация | North star и метрика каждого этапа CJM; монитор генерации с повтором; алерты в Telegram (источники, бюджет и сбои LLM, отклонённые инсайты, зависшие запуски, ML); Prometheus — HTTP, LLM, сбор новостей, генерация; резервные копии Postgres и S3 | `docs/METRICS.md`, ADR-034, ADR-046 |
| Безопасность | JWT и доступ по компаниям; LLM только через Gateway; маскирование PII; rate limit; запрет dev-секретов в prod; защита сборщика от SSRF | `docs/SECURITY.md` |
| Развёртывание | Бэкенд, ML и фронтенд — отдельные сервисы Dokploy; автодеплой из CI после зелёных тестов | ADR-032, `docs/RUNBOOK.md` |

## Как проверено

| Проверка | Результат |
|---|---|
| Lint, типы (ruff, mypy strict для domain и services) | зелёные |
| Unit | 484 (проверка 26.10, `docs/VERIFICATION.md`) |
| Integration (Postgres + pgvector, Redis, MinIO) | 84 + отдельно OCR с настоящим Tesseract в Docker |
| E2E | 23 с заглушкой + 3 с настоящим ML в режиме правил |
| CI GitHub Actions | lint, типы, unit, integration, e2e, тесты ML, сборка фронтенда; деплой только после зелёных |
| Автоматизированный сценарий демонстрации | `scripts/demo_check.py`, 14 шагов; сквозной API-сценарий проверен в изолированном compose |
| Удалённый стенд (26.10) | вход demo, 3 компании, разные ленты двух компаний, источники и персонализация в карточках проверены по API; платная LLM и полный браузерный сценарий в этот аудит не входят |

Покрытие критериев и ограничений кейса — таблица трассировки в `docs/SPEC.md` §3.

## Границы ответственности

- **ML-сервис** (`ml/`) — агент генерации инсайтов, ответы на вопросы, ранжирование, выбор моделей. Бэкенд даёт
  контракты (`contracts/`), инструменты, Gateway, проверку результата и `ml-stub` для e2e.
- **Фронтенд** (`frontend/`) — интерфейс по `docs/openapi.json` и `docs/INTEGRATION_FRONTEND.md`.

## Ограничения

`docs/SPEC.md` §16. Главные:
- ориентировочные тарифы LLM заданы в конфигурации; фактический баланс и условия определяет провайдер;
- графики и таблицы в PDF распознаются частично;
- фильтр законодательства — правила, а не юридическая экспертиза; реестр сайтов сверяется с официальными
  реестрами вручную.

Направления развития — `docs/ROADMAP.md`.
