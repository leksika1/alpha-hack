# Входные данные: профиль и правила очистки

Профилирование выполнено 2026-10-22 по `data/raw/` (скрипт будет оформлен как `scripts/profile_raw.py` в фазе 1).
Сырые данные организаторов **не коммитятся** (`.gitignore`). Без них система работает на `data/synthetic/`.

## Общий формат CSV

- Разделитель `;`, кодировка UTF-8, первая строка — заголовок.
- Флаги в виде `0.0` / `1.0` → `boolean`.
- Кавычки встречаются только в `df_Fid_Uid_link_hack.csv` (`"Мск ""Юг"""`) — стандартное CSV-экранирование.
- Пустая строка = отсутствующее значение (`NULL`).

## df_Uid_data_hack.csv — юрлица

85 525 строк, 24 колонки, **85 514 уникальных `SYNTHETIC_U`**.

| Колонка | Наблюдение | Правило |
|---|---|---|

| `ORG_TYPE` | константа `КОММ_ОРГ` | хранить, в признаки не включать |
| `OKFS_NAME` | 12 значений; 96% «ЧАСТНАЯ СОБСТВЕННОСТЬ» | признак `ownership_form`; флаг `foreign_ownership` для «иностран*» |
| `COMPANY_AGE_YEARS_GRADATION` | `0-3`, `4-7`, `8-15`, `16-25` | категория `age_bucket` |
| `ECO_MARK_LABEL` | 4 значения + **4 157 пустых** | стадия жизненного цикла; пустое → NULL + `data_completeness` |
| `MAINOKVED_CODE` | 546 кодов, форматы `99`, `99.9`, `99.99`, `99.99.9`, `99.99.99` | нормализовать в класс (`XX`), группу (`XX.X`), подкласс; секция A–U через справочник |
| `MAINOKVED_NAME` | 536 названий (на 546 кодов) | хранить как есть |
| `NEGATIVEMARK` | 1.0 у 11 076 (13%) | `has_reliable_owner_info` (FAQ п.13: есть ли у банка достоверные сведения о ключевом собственнике) |
| `AMOUNT_WORKERS_FNS_GRADATION` | 4 градации, без пропусков | `staff_bucket` |
| `AMOUNT_WORKERS_SPARK_GRADATION` | **99,8% пустые** (168 значений) | хранить, в признаки не включать |
| `CL_TYPE` | CLIENT 41 968 · PROSPECT 36 699 · CLOSE_CLIENT 6 858 | хранить всё; демо-доступ и генерация инсайтов только для CLIENT (FAQ п.11–12, 57) |
| `CL_PRODUCT_*_MARK` | у CLIENT: РКО 94,5%, ЗПП 56%, лизинг 27%, кредит 11%, депозит 9%, гарантия 6% | `company_products`; кредит/лизинг → `rate_sensitive` |
| `FTS_FLAG` | 8 364 = 1 | `fx_sensitive`; **рассогласование**: 206 строк с флагом 0, но со странами; 224 строки с флагом 1 без стран — флаг вычислять как `FTS_FLAG OR countries≠∅`, рассогласование в отчёт качества |
| `FTS_COUNTRY_NAME` | строка «ОАЭ, ИНДИЯ, КИТАЙ», 128 стран, топ: Китай 5 761, Турция 1 698, Индия 1 019 | нормализовать в `company_fts_countries` (только страны, без направления — FAQ п.19) |
| `FACTORING_MARK` | 213 компаний | продукт `factoring` |
| `REVENUE_COMPANY` | рубли, 2025 г. (FAQ п.14); **601 строка = 1000** (заглушка), min=1000, max=1,06·10¹¹ | `1000` → `revenue_rub=NULL`, флаг `revenue_stub=true` |
| `GROUP_ID` | формат `group_<n>_sb`, 18 098 групп, без пропусков; 12 869 групп — из одного юрлица; крупнейшая — 624 юрлица | `company_groups` с агрегатами; выручка группы — сумма валидных выручек |
| `CITY` / `REGION` | 267 городов / 82 региона | признаки региона; нормализация названий регионов — справочник |

Масштаб: юрлиц с выручкой > 15 млрд — **115**; групп с суммарной выручкой > 15 млрд — **341**.
Сегмент «крупный бизнес» определяется по выручке группы (FAQ п.16), но группа > 15 млрд может быть и в среднем
сегменте, поэтому `segment` — производный признак с источником `derived`, а не фильтр.

## df_Fid_Uid_link_hack.csv — физлица ↔ компании

12 514 строк: `SYNTHETIC_F`, `CITY_NAME` (город обслуживания), `RC_NAME` (регион обслуживания — FAQ п.18), `SYNTHETIC_U`.

- 11 120 физлиц, 12 307 компаний, полных дублей нет.
- **Только 36,7% компаний из этой таблицы есть в таблице юрлиц** → остальные связи сохраняем, но в граф между
  известными компаниями они не дают рёбер.
- 969 физлиц связаны с > 1 компанией (максимум — 25) → рёбра `shared_person` (вес — число общих физлиц).
- `RC_NAME`: федеральные округа + мусорные значения (`''` — 14, «ИНН не определён» — 7, «Не определено» — 1) → NULL.
- Идентификаторы физлиц — чувствительные: **не уходят в LLM** (маскируются в Tools API и Gateway).

## Аналитика Альфа-Банка (9 PDF, ~87 МБ)

**Все 9 PDF — сканы без текстового слоя** (по одной картинке ~1357×1920 на страницу, Quartz PDFContext).
Текстового слоя нет (0 символов) → пайплайн обязан включать OCR (ADR-005, ADR-023).

| Файл | Стр. | Тема |
|---|---|---|
| `ALFA-7M26.pdf` | 4 | макростатистика 7М26 |
| `ALFA-macro_stat1H26.pdf` | 5 | макростатистика 1П26 |
| `ALFA-Macro_Insights-Policy_Rate_11Sep.pdf` | 4 | ключевая ставка (11.09.2026, 14,0%) |
| `ALFA-consumption.pdf` | 4 | потребление |
| `ALFA_Russian_Steels_1К21PreviewUpdate_15Apr2021.pdf` | 4 | commodities / сталь |
| `FI_Strategy_3Q26_22072026.pdf` | 27 | стратегия на рынке облигаций 3К26 |
| `Gold_digest_August26.pdf` | 8 | золото |
| `Inflation_tracker_02.pdf` | 3 | инфляция |
| `Бонд_Бриф_14092026.pdf` | 5 | Бонд Бриф |

Итого 64 страницы. Качество скана хорошее (печатный текст, таблицы, графики). Дата документа — из текста
первой страницы (OCR) либо из имени файла; при неуверенности — `NULL` + флаг. Пайплайн общий: новые PDF
кладутся в S3/`data/raw/analytics/` и проходят те же шаги (текстовый слой → иначе OCR).

Ограничения импорта: `ANALYTICS_MAX_BYTES=50000000`, `ANALYTICS_MAX_PAGES=150`,
`ANALYTICS_MAX_RENDER_PIXELS=25000000`. На больших страницах разрешение OCR уменьшается до предела
пикселей. PDF с пустым результатом извлечения не публикуется. Импорт каталога принимает `.pdf`/`.PDF`,
продолжает обработку остальных файлов при повреждённом PDF и возвращает код 1, если хотя бы один файл
не обработан; подробности остаются в JSON-отчёте CLI.

### Результат OCR и нарезки (фаза 4, 2026-10-23)

Итого 202 фрагмента. Что отфильтровано и почему (правила общие, не под файлы — ADR-024):
- строки OCR со средней уверенностью < 0,65 — подписи и «штриховка» графиков (`[== [== ©`);
- абзацы-оси и легенды графиков (мало слов, много обрывков) — ~430 абзацев на 64 страницы; таблицы с подписями
  (мультипликаторы сталеваров, рейтинги эмитентов) сохраняются;
- юридический дисклеймер (раздел «Контакты и дисклеймер», фразы «Все права защищены», «не является
  инвестиционной рекомендацией»), подписи «Источники: …», повторяющиеся колонтитулы;
- даты в теле документа вроде «погашение 13.10.2040» не принимаются за дату выпуска: приоритет — дата в шапке,
  затем в имени файла.

Проверка поиска (8 бизнес-запросов: ставка, сталь, ОФЗ, рынок труда, золото, потребление, бюджет, недельная
инфляция) — первый результат из профильного документа с верной страницей во всех 8 случаях. Остаточный шум —
отдельные цифры с графиков внутри абзацев; извлечение графиков и таблиц — VLM (BACKLOG).

## Отчёт качества данных

Ingest формирует `data_quality_report` (таблица + `GET /admin/data-quality`): дубли ID, заглушки выручки,
пропуски по колонкам, рассогласование FTS-флага, висячие ссылки (платежи/физлица → неизвестные компании),
самопереводы, мусорные значения справочников.

## Синтетический набор (`data/synthetic/`, `make synthetic`)

Детерминированный (seed 2026), в формате оригинальных CSV: 2 424 строки компаний, 20 930 строк платежей, 765 связей.
Воспроизводит особенности реальных данных: коллизия ID (`U_799999`, 3 строки), заглушки выручки, пустые ECO-метки,
расхождения ФТС-флага, самопереводы, неизвестные контрагенты, дубли пар платежей, мусор в `RC_NAME`, кавычки в городах.
Пять демо-компаний CLIENT из разных отраслей (`data/synthetic/demo_companies.json`): металлоторговля `U_700001`,
продуктовая розница `U_700002`, грузоперевозки `U_700003`, зерновой агрохолдинг `U_700004`, девелопер `U_700005`;
они связаны платежами между собой и с поставщиками/покупателями профильных отраслей.
