# Правила работы агента (подробно)

Краткая версия — в корневом `CLAUDE.md`. Здесь — детали процесса.

## Цикл работы

1. Прочитать `CLAUDE.md`, `docs/PROGRESS.md`.
2. Взять одну задачу (первая `[ ]` текущей фазы). Пометить `[~]`.
3. Сверить со `docs/SPEC.md`. Если в спеке пробел → ADR в `docs/DECISIONS.md` (формат ниже), продолжить.
4. Реализовать, написать тесты, прогнать `make check`.
5. Обновить docs/OpenAPI/PROGRESS. Закоммитить.

## Приоритеты при нехватке времени

Сквозной сценарий работает → данные реальные → полнота фич → полировка.
Если задача фазы N блокирует сквозной сценарий, она важнее любой задачи полировки.

## Definition of Done

| Пункт | Проверка |
|---|---|
| Код | реализует требование из SPEC, без «улучшений» вне задачи |
| Тесты | unit на логику; integration на БД/S3/очереди/HTTP-коннекторы; e2e — если меняется пользовательский сценарий |
| `make check` | зелёный локально |
| Документация | затронутые `docs/*.md` обновлены; `make openapi`, если менялись роутеры/схемы |
| PROGRESS | статус задачи, «Следующий шаг» |
| Коммит | Conventional Commits, один логический шаг, без секретов и `data/raw/` |

## Формат ADR (`docs/DECISIONS.md`)

```
## ADR-NNN: <заголовок>
- Дата: YYYY-MM-DD · Статус: принято | заменено ADR-MMM
- Контекст: ...
- Решение: ...
- Альтернативы: ...
- Последствия: ...
```

## Изменение контрактов (`contracts/`)

1. ADR с обоснованием.
2. Bump `schema_version` (semver: patch — описание/примеры, minor — новые необязательные поля, major — ломающие).
3. Запись в `contracts/CHANGELOG.md`.
4. Обновить зеркальные Pydantic-модели (`app/domain/contracts/`) и примеры `contracts/examples/`; `tests/unit/test_contracts.py` должен пройти.
5. Если контракт уже передан ML/фронту и изменение ломающее — **остановиться и спросить человека**.

## Когда останавливаться

См. `CLAUDE.md` §6. Во всех прочих случаях — принимать решение, фиксировать ADR, продолжать.

## Работа с данными организаторов

- `data/raw/` не коммитится и не читается инструментами чтения файлов агента; читают только скрипты ingest/profiling.
- Отсутствующие данные не восстанавливаются «по аналогии» — `NULL` + флаг полноты.
- Профили неизвестных контрагентов не выдумываются (FAQ п.22).
