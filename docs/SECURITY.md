# Безопасность бэкенда

Сводка мер по SPEC §13 и ограничению О6. Решения — в `docs/DECISIONS.md` (ADR-010, 020, 028).

## Доступ

| Кто | Как | Что может |
|---|---|---|
| Пользователь | JWT access (30 мин) + refresh (7 дн.), пароли — scrypt | только компании из `user_company_access`; чужая компания → 403 |
| Админ | JWT с `platform_role=admin` | `/api/v1/admin/*` |
| Агент (ML) | run-токен на один запуск + `X-Run-Id` | Tools API только по компании запуска, только чтение (кроме `log_step`); бюджет вызовов на запуск; LLM Gateway |
| ML-сервис | `ML_SERVICE_TOKEN` | LLM Gateway; вызовы бэкенд → ML |

Агент не выполняет действий, меняющих состояние: CRM-заявку создаёт только пользователь (`POST /insights/{id}/actions`).

## LLM (ADR-028)

- Только 6 моделей из белого списка кейса и только через `/internal/llm`; прямых вызовов провайдера в коде нет.
- Перед отправкой маскируются ID физлиц, e-mail, телефоны, ИНН/ОГРН/счета; в журнал попадает маскированное превью ≤ 500 символов.
- Жёсткий дневной бюджет с резервированием (параллельные вызовы не превышают лимит) и лимит токенов; исчерпан → 429,
  агент работает без LLM.
- Тексты новостей передаются агенту как данные (`trust: untrusted`, `<untrusted_content>`); строки с подозрением на
  prompt injection вырезаются из лида, новость помечается (ADR-020).

## Ограничение нагрузки

Token bucket в Redis на вызывающего (хэш bearer-токена; без токена — IP, так ограничен и подбор пароля на `/auth/login`):
`RATE_LIMIT_PUBLIC_PER_MIN` для `/api/v1`, `RATE_LIMIT_INTERNAL_PER_MIN` для `/internal`. Ответ — 429 problem+json с
`Retry-After`. Если Redis недоступен, запросы пропускаются (fail open, повторная попытка через 30 с), в лог —
предупреждение: доступность ленты важнее лимита.

## Данные и журналы

- Логи — JSON с маскированием ID физлиц, e-mail, телефонов (`app/core/logging.py`).
- Аудит: каждый вызов инструмента — `tool_audit_log`, каждый вызов LLM — `llm_usage`, шаги агента — `agent_steps`.
- Сырые данные организаторов (`data/raw/`) и `.env` не коммитятся; секреты — только из env.
- `APP_ENV=prod` с dev-значениями `JWT_SECRET`, `SERVICE_TOKEN`, `ML_SERVICE_TOKEN` не стартует.
- Новости, присланные пользователем, не попадают к другим клиентам: событие приватно для компании отправителя,
  пока его не подтвердит настоящий источник; не больше 30 в сутки (ADR-038).
- Сбор новостей — только публичные адреса (http/https, 80/443): источники, которые добавляет админ, не могут
  увести сборщик во внутреннюю сеть, в том числе через редирект (SSRF, ADR-036).
- Токен Telegram-бота алертов — секрет (`TELEGRAM_BOT_TOKEN`); в логи и тексты ошибок не попадает (ADR-034).
- Ссылки на PDF аналитики — через API с токеном на один документ на 15 минут (ADR-033); S3 наружу не открыт.
