# Метрики качества и продукта

Метрики построены по CJM финансового директора («от значимого события до решения для бизнеса», 8 этапов).
Считаются в `app/services/metrics.py`. Живой срез отдаёт `GET /api/v1/admin/metrics?days=N`. Ежедневный снимок
пишется в `core.metrics_daily` задачей `metrics.snapshot` (00:30 UTC) и попадает в поле `daily` того же ответа.

## Откуда данные

- **Лог событий `core.user_actions`.** Бэкенд пишет его сам; клиент присылает только события, которые видит лишь
  интерфейс (`POST /api/v1/events`).
- **Таблицы:** `feedback`, `qa_messages`, `crm_requests`, `insights`, `agent_runs`, `insights_rejected`.
- **Сессия** — события одного пользователя без перерыва 30 минут и больше.

| Событие (`action_type`) | Кто пишет | Где |
|---|---|---|
| `summary_view` | API | `GET /feed/summary` — показан виджет на главной |
| `widget_shown`, `widget_click`, `card_impression`, `profile_prompt_shown`, `digest_opened` | клиент | `POST /events` |
| `feed_view` | API | `GET /feed` (первая страница) |
| `insight_open` (`via`, `position`) | API | `GET /insights/{id}?via=feed&position=3` |
| `trace_view`, `source_click` | API | трассировка, переход к источнику |
| `ask` | API | вопрос к инсайту или по компании |
| `cta`, `watch` | API | заявка в мок-CRM, «наблюдать» |
| `feedback`, `hide`, `unhide`, `save`, `open` | API | отзыв и состояния карточки |
| `profile_update`, `role_switch` | API | анкета, смена роли |
| `notification_open`, `digest_view` | API | переход из уведомления, дайджест |

## North star и метрики этапов CJM

| Метрика | Определение | Поле ответа |
|---|---|---|
| **North star** | Доля сессий, где пользователь отметил инсайт полезным **и** выбрал следующий шаг (заявка или «наблюдать») | `north_star.value` |
| Скорость | Медиана времени от начала сессии до первой оценки «полезно» | `speed.median_s_to_first_useful` |
| Качество | Доля «полезно» среди оценок; полезность в топ-5; доля ключевых выводов с источниками | `quality.*` |
| Возврат | Доля пользователей, вернувшихся через 1–7 дней; число скрытий | `return.*` |
| 01 Заметить сервис | Доля сессий с показом виджета, в которых открыли ленту или инсайт | `cjm.01_notice` |
| 02 Подтвердить контекст | Доля сессий с исправлением профиля; медиана времени до первой открытой карточки | `cjm.02_context` |
| 03 Выбрать важное | Доля «полезно» среди оценённых инсайтов, открытых с позиций 1–5 ленты | `cjm.03_select` |
| 04 Понять последствия | Доля верно объяснивших влияние — опрос или экспертная оценка; из логов не считается (`null`) | `cjm.04_understand` |
| 05 Проверить основания | Доля ключевых утверждений (`fact`, `bank_analytics`) с источниками; доля инсайтов с позицией банка | `cjm.05_verify` |
| 06 Уточнить сценарий | Доля вопросов, после которых инсайт отмечен полезным (в течение 30 мин); доля ответов, прошедших проверку | `cjm.06_clarify` |
| 07 Выбрать действие | Доля заявок, доведённых до `done`; «наблюдать» — отдельно | `cjm.07_act` |
| 08 Оценить и вернуться | Доля вернувшихся за 7 дней; скрытия; причины «бесполезно» | `cjm.08_return` |

## Генерация

| Метрика | Определение |
|---|---|
| `generation.rejected_share` | Доля инсайтов, отклонённых валидатором, среди готовых и отклонённых |
| `generation.reject_reasons` | Топ причин отклонения (коды валидатора) |
| `failed`, `skipped` | Сбои агента; пропуски по нерелевантности |
| Расход LLM | `GET /api/v1/admin/llm-usage` (ADR-028) |

## Процесс

1. Ежедневно смотреть north star, `useful_share` и долю отклонённых. Если `useful_share` падает, смотреть
   `not_useful_reasons`:
   - `irrelevant` — к ML-команде (скорер, матчинг);
   - `wrong` — к валидатору и источникам;
   - `obvious` — к шаблонам и промптам ML.
2. Отклонения валидатора по кодам передавать ML-команде вместе с `insights_rejected.payload`.
3. Этап 04 и спорные случаи проверять раз в неделю вручную на выборке из 20 инсайтов с оценками экспертов
   банка; размечать «верно ли объяснено влияние» и «проверяемы ли выводы».
