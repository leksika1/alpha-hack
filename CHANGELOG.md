## [1.1.0] — 2026-10-26

Версия для сдачи онлайн-этапа (`docs/REPORT.md`).

### Добавлено
- Демо: любая компания клиентской базы по ID — поиск `GET /companies/search`, `POST /me/companies` (ADR-048).
- Демо-лента уходит из лент, когда реальные источники дали новости; первый сбор новостей и данных ЦБ — сразу
  после старта (ADR-049).
- Памятка сдачи `docs/SUBMISSION.md` по странице 8 задания, актуальная трассировка требований и перечень
  production-зависимостей фронтенда; дополнены notices образов, шрифтов и имитируемой CRM.
- Самостоятельная документация всего проекта: `docs/PROJECT_GUIDE.md` и PDF для передачи;
  руководство разработчика `backend/README.md`, актуальные инструкции интеграции и отчёт `docs/VERIFICATION.md`.
- `SCORER_PROVIDER=remote` подключён к матчингу бэкенда: батчи `/v1/score`, baseline при ошибке и снятие
  утративших релевантность карточек; миграция 0011 хранит полное имя ML-скорера.
- `make e2e-ml`: очередь, настоящий ML-сервис, Tools API, валидированная лента, трасса, вопросы и скоринг;
  изолированный запуск без платной LLM, включён в CI.
- Тарифы моделей организаторов по умолчанию, день бюджета LLM — с 03:00 МСК, как у провайдера; остаток лимита у
  провайдера — `GET /admin/llm-provider`.
- Ключевая ставка и официальные курсы ЦБ (доллар, евро, юань) раз в час: инструмент агента `get_market_data`,
  `GET /market` для виджета, `POST /admin/market/refresh` (ADR-043).
- Источники: отраслевые рубрики «Ведомостей» и страницы новостей Минтранса, Минсельхоза, Минэкономразвития и ФНС —
  новый вид источника `html` для сайтов без RSS (ADR-044).
- Справочник 89 регионов РФ: тегер находит регион по городам, `REGION` и `CITY` компаний приводятся к одному
  написанию (ADR-045).
- Метрики сбора новостей и генерации в Prometheus (`/metrics`).
- Резервные копии Postgres и S3 по расписанию — сервисы `backup-db` и `backup-s3` (ADR-046).
- `LLM_PROXY_URL`: вызовы LLM-провайдера через прокси, если он недоступен из сети сервера (ADR-041).
- Лента «Все»: не больше `FEED_TOPIC_CAP` карточек одной макротемы (денежно-кредитная политика, курс), у
  показанных — `more_in_topic` (ADR-042).
- Алерт `llm-errors`: больше половины вызовов LLM за час завершились ошибкой (ADR-042).
- LLM организаторов по умолчанию: адрес `https://api.alfahack-gateway26.ru/v1` и ID всех 6 моделей; для
  подключения нужен только `LLM_API_KEY`. Без ключа Gateway отвечает `llm-not-configured`, не обращаясь к провайдеру.
- Зарубежные источники по умолчанию (15 лент), английский тегер и язык новости; недоступный источник
  пропускается, алерт — только при массовой недоступности (ADR-039).
- Пользователь присылает ссылку или текст новости (`POST /news/submit`): общий конвейер, инсайт для своей
  компании; недоступный ресурс — «Ресурс сейчас недоступен для просмотра» (ADR-038).
- Соответствие законодательству РФ: правила для новостей, инсайтов и ответов, реестр сайтов (ADR-037).
- Админ: поиск лент по названию сайта (справочник российских и зарубежных изданий) или по ссылке на сайт
  (`/admin/sources/discover`); при добавлении можно указать ссылку на сайт — лента найдётся сама.
- Админ: источники новостей (`/admin/sources`) — проверка ленты, добавление RSS/Atom без деплоя, включение и
  выключение (в том числе источников каталога), удаление своих; сборщик ходит только на публичные адреса (ADR-036).
- Админ: загрузка PDF аналитики (`POST /admin/analytics`, тело — файл) и статусы обработки (`GET /admin/analytics`):
  файл сразу виден как `processing`, воркер прогоняет обычный конвейер (FR-A7).
- Алерты (ADR-034): раз в 5 минут — упавшие источники, бюджет LLM, доля отклонённых инсайтов, зависшие запуски,
  недоступный ML; в Telegram (`ALERTS_PROVIDER=telegram`) или в лог, не чаще раза в час; `GET /admin/alerts`.
- LLM Gateway: вопросы к аналитике тратят не больше `LLM_CHAT_BUDGET_SHARE` (30 %) дневного бюджета — остальное
  остаётся генерации ленты (ADR-035).
- Админ: монитор генерации (`GET /admin/generation`: очередь, кандидаты по статусам, запуски за сутки с p50/p95,
  зависшие запуски, последние ошибки, доступность ML) и повтор (`POST /admin/generation/retry`).

### Исправлено
- Запуск по `.env.example` падал на миграции: Docker Compose читал `VAR=   # комментарий` как значение
  «# комментарий» (`LLM_MODEL_MAP`, `LLM_BASE_URL`, `LLM_API_KEY` …); комментарии перенесены на свою строку,
  тест следит за форматом.
- Локальный запуск не стартовал при занятых портах 5432/6379/9000: инфраструктура слушает только `127.0.0.1`
  на портах 15432/16379/19000.
- Без ключа LLM висел критический алерт «LLM-провайдер не отвечает»: отсутствие ключа — режим, а не сбой.
- Пользовательская новость текстом принимается от 40 символов (было 100).
- Пресс-релизы ЦБ о памятных и инвестиционных монетах больше не становятся инсайтами; генерация чередует
  компании, чтобы все ленты заполнялись одинаково.
- Совместимость Gateway с новым ML: если провайдер явно отвергает optional-поля `chat_template_kwargs`
  или `response_format`, запрос повторяется без них, независимо от лимита транспортных повторов.
- Настройки таймаутов, rate limit, SSE, дайджестов, CORS и кэша LLM из `.env` передаются в контейнеры бэкенда.
- Тариф сценария исчерпания бюджета зафиксирован в тестовом окружении, независимо от цен провайдера.
- LLM Gateway отклоняет повреждённые JSON-ответы провайдера как `502 llm-invalid-response` и освобождает
  резерв бюджета; проверяются также поля usage и ответ о балансе ключа.
- Интеграция с ML: новый ключ идемпотентности при перегенерации, проверка служебного ответа генератора,
  запись ошибок повреждённого SSE, согласованные таймауты вопросов и срок run-токенов на все HTTP-повторы.
- LLM по умолчанию — адрес организаторов для российского хостинга `https://api.alfahack-gateway26.ru/v1`: прежний
  (https://changellenge.up.railway.app/v1) с сервера в РФ недоступен (ADR-041).
- Демо-лента больше не склеивается с реальными новостями в одно событие; cleanup разделяет уже смешанные (ADR-040).
- Лента (ADR-040): ставка в карточке — из решения ЦБ, а не из прогноза; решение ЦБ и комментарии к нему — одно
  событие (вместо 6–7 карточек); онлайн-трансляции не становятся инсайтами; новости о ФРС/ЕЦБ больше не
  считаются решением Банка России. `POST /admin/news/cleanup` чинит уже накопленные данные.
- LLM Gateway: резерв бюджета, чей вызов оборвался (агент не дождался ответа) или остался без результата,
  больше не висит в `pending` и не занимает дневной бюджет; в `/admin/llm-usage` и трассе виден код ошибки вызова.
- Воркер: процессы падали и перезапускались каждые несколько секунд простоя — redis-py 8 читает с таймаутом 5 с,
  а ожидание задачи (BRPOP) бесконечное; задача, которая в этот момент выполнялась, терялась.
- Ссылки на страницу PDF аналитики не открывались на сервере (presigned на `localhost:9000`): теперь PDF отдаёт API
  по ссылке с токеном на документ, 15 минут (ADR-033). `S3_PUBLIC_ENDPOINT_URL` больше не нужен.

### Изменено
- Compose разделён по частям (ADR-032): `<часть>/docker-compose.yml` — сервис Dokploy без портов на хосте,
  `<часть>/docker-compose.override.yml` — локальные порты; бэкенд, ML и фронтенд; корневой `docker-compose.yml` подключает
  их через `include`, запуск из корня не изменился (`make up`). Части общаются через `dokploy-network` по `BACKEND_ALIAS`.
- Фронтенд: адрес бэкенда для nginx — `BACKEND_UPSTREAM`, резолвится при запросе (фронтенд стартует без бэкенда).

### Добавлено
- CI: сборка образа фронтенда; проверка compose-файлов частей; задание `deploy` — вебхуки Dokploy после зелёных
  тестов: `main` → окружение prod, `dev` → dev, матрица backend / ml / frontend (часть без compose-файла пропускается).

- `POST /api/v1/admin/news` — ручной ввод новости (пресс-релиз, сообщение аналитика) через общий конвейер.

### Добавлено (фаза 6 — доставка по CJM)
- Уведомления: срочные инсайты, дайджест дня/недели, статусы заявок; список и SSE-поток с `Last-Event-ID`.
- `GET /digest`; вопросы к аналитике `POST /insights/{id}/ask`, `POST /ask` (SSE, проверка ответа агента, история).
- Карточка: «почему это для вас», причины приоритета, отметка «обновлено»; «наблюдать»; ответ на отзыв.
- `GET /me/requests`; admin: метрики north star и этапов CJM, качество данных, здоровье источников, запуск сбора,
  перегенерация, статусы заявок; `docs/METRICS.md`.

### Добавлено (фаза 5 — инфраструктура агента)
- LLM Gateway `/internal/llm`: белый список из 6 моделей, дневной бюджет в ₽ и токенах с резервированием (жёсткий
  стоп и при параллельных вызовах), маскирование PII, кэш детерминированных запросов, журнал `llm_usage`, стриминг.
- `GET /api/v1/admin/llm-usage`; вызовы LLM в трассировке инсайта (`llm_calls`); агенту передаётся `allow_llm=false`
  при исчерпанном бюджете.
- Rate limit (Redis token bucket) для `/api/v1` и `/internal`; запрет запуска `APP_ENV=prod` с dev-секретами.
- Матчинг события по всей клиентской базе через предфильтр по индексу (`MATCH_SCOPE`), худшее событие на данных
  организаторов — 3,0 с.

### Добавлено (фаза 4 — аналитика банка)
- Загрузка PDF аналитики: S3 по sha256, текстовый слой или OCR Tesseract (rus+eng) с кэшем результатов в S3,
  чанкинг по разделам со страницами, метаданные (название, дата, темы).
- Эмбеддинги за `EmbeddingProvider` (`fake`, `local` — fastembed, `remote`; модель выбирает ML-команда) и переиндексация.
- Гибридный поиск (pgvector HNSW + полнотекстовый `russian` + RRF) с цитатами страниц для Tools API `search_bank_analytics`.
- `GET /api/v1/analytics/documents`, `GET /api/v1/analytics/documents/{id}/download` (presigned URL с `#page=N`);
  переход к источнику `bank_analytics` ведёт на страницу PDF.
- Синтетические демо-PDF (помечены «ДЕМО (синтетика)»), `make ingest-analytics`, задача воркера `analytics.ingest`.
