# ML: что сделано и что делать дальше

Статус на 23.10.2026: ML-сервис влит в `dev`. Он работает без LLM на аналитике `rules@1`, и все сгенерированные
инсайты проходят валидатор бэкенда. Ключ LLM получен, но **адрес API провайдера (`LLM_BASE_URL`) организаторы
не прислали**: без него LLM-путь не включится. Дедлайн — 26.10, 18:00.

## 1. Подключить LLM (блокер, сегодня)

1. Узнать у организаторов (через капитана команды AstraMax-CU) `LLM_BASE_URL` и точные ID моделей у провайдера.
   Нужен OpenAI-совместимый адрес вида `https://…/v1`.
2. Ключ **не коммитить и не писать в чаты**. Записать только в секреты Dokploy или в локальный `.env` (он в `.gitignore`):
   ```env
   LLM_BASE_URL=https://<от организаторов>/v1
   LLM_API_KEY=<ключ команды>
   LLM_MODEL_MAP={"gemma-4-26b-a4b":"<id>","qwen3.6-35b-a3b":"<id>","glm-5.3-flash":"<id>"}
   LLM_PRICES={"gemma-4-26b-a4b":[<₽ вход>,<₽ выход>], ...}   # если организаторы дадут тарифы
   LLM_DAILY_BUDGET_RUB=450                                  # жёсткий стоп Gateway, запас 50 ₽
   ```
3. Проверить связь одним дешёвым вызовом (≈0,01 ₽):
   ```bash
   curl -s $LLM_BASE_URL/models -H "Authorization: Bearer $LLM_API_KEY"          # список ID моделей
   make smoke-live                                                              # проверка Gateway бэкенда
   ```
4. Перезапустить стек: `docker compose up -d --build`. В трассе инсайта должны появиться шаги `llm_call`,
   а в `models_used` — модели из белого списка.

## 2. Экономия токенов (500 ₽ в день)

Что уже настроено:
- LLM пишет только инсайты с предварительной релевантностью ≥ `ML_LLM_MIN_SCORE=0.5`. Остальные пишет
  `rules@1` бесплатно.
- Нерелевантные пары отсекаются до любых вызовов (`ML_SKIP_THRESHOLD=0.35`).
- Раунд исправления после критика — не больше одного (`ML_MAX_ITERATIONS=1`).
- При `temperature=0` Gateway кэширует ответы: повторная генерация бесплатна.
- Бюджет Gateway — 450 ₽ в день, жёсткий стоп. При 429 сервис переходит на `rules@1`.
- Оценка стоимости: ≈ 1,4–1,8 ₽ на LLM-инсайт и ≈ 0,4 ₽ на ответ в чате.

Если бюджет тает быстро, переключатели такие (по убыванию эффекта):
`ML_LLM_CRITIC=false` (−30%), `ML_LLM_PLANNER=false` (−15%), `ML_LLM_MIN_SCORE=0.7`.
**Не гонять** `eval.run_eval --llm-base-url` по всем 150 парам: для проверки хватит 10–15 пар (~25 ₽).
Расход смотреть в `GET /api/v1/admin/llm-usage`.

## 3. Проверка на живой LLM (после п.1)

1. Пройти 5–10 инсайтов демо-компаний и чат по ним, посмотреть трассы. Проверить, что LLM отвечает JSON-ом;
   если нет — в шагах трассы видно `answer is not JSON`, и сервис сам откатывается на `rules@1`.
2. Если модель плохо держит JSON или русский — поменять `ML_MODEL_ANALYST` (кандидаты: `deepseek-v4.1-flash`,
   `kimi-k2.6`), код трогать не нужно.
3. Обновить `reports/eval.md` прогоном на 15 парах с LLM и сравнить с `rules@1`.
