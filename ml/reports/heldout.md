## Как читать этот отчёт (честность оценки)

Набор: 15 новостей ленты Интерфакса за 23–24.10.2026 (не использовались при настройке) × 10 реальных клиентов из
данных организаторов (5 кандидатов в демо + 5 случайных, seed 2026) × 2 роли = 300 пар. Разметка
(`eval/heldout/labels_2026-10-23.json`) сделана по профилям компаний **до** первого прогона; порог показа 0,35 не менялся.

**Первый прогон (чистая отложенная оценка, код до правок):**

| Роль | Скорер | nDCG@5 | Recall важных | Доля нерелевантных |
|---|---|---|---|---|
| cfo/ceo | baseline@1 (бэкенд) | 0.771 | 0.94 | 0.355 |
| cfo/ceo | ml-ranker@1 | 0.73 | 0.94 | 0.073 |

Найденные ошибки: (1) «рубль вырос к юаню» трактовалось как рост юаня → заголовок «импорт подорожает» (обратный
знак); (2) валюта события (EUR) засчитывалась как связь с ВЭД для неденежных новостей (Vonovia, топливо в ЕС →
агротрейдер с ВЭД в Италии); (3) новость об ИТ-ипотеке не доходила до застройщика (тег только `real_estate`);
(4) госзакупки зерна для зернотрейдера — «давление на себестоимость» вместо поддержки цен.

**После правок** (таблица выше) — уже не отложенная оценка для этого набора: правки сделаны по его ошибкам, но
они общие (направление курса, валюта только для FX-событий, ипотека → стройка, спрос/закупки для продавца), без
правил под конкретные новости. Для следующей честной оценки нужен новый набор: `eval/heldout/news_<дата>.json` +
разметка до прогона.

Ошибка тегирования бэкенда для сведения: «МРОТ … медианной зарплаты» получает сырьё `nonferrous` — стоит проверить словарь `tagging.py` (бэкенд).
