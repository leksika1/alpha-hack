# Критерии кейса → ML-часть: где смотреть и как проверить

Критерии — раздел «Критерии успеха» кейса (стр. 8–9). Столбец «Проверка» — команда или место в интерфейсе.

| № | Критерий | Что сделано в ML | Где в коде / документах | Проверка |
|---|---|---|---|---|
| 01 | Бизнес-контекст клиента, отбор значимых событий | Подверженность компании событию по признакам `company_context` (продукты, ВЭД, отрасль, доли контрагентов, сырьё, регион, анкета); порог показа; `skipped` для нерелевантного | `alfa_ml/profile.py`, `ranker.py`, ADR-ML-002/005 | `reports/eval.md`: recall важных 1,0, доля нерелевантного 0,20 vs 0,51 у baseline; `reports/heldout.md`: 0,07 vs 0,36 на новых новостях × реальных клиентах |
| 02 | Содержательная интерпретация, не пересказ | Цепочка «событие → фактор → показатель компании» по нескольким факторам, риски/возможности с горизонтом и драйверами, сценарии с сигналами, количественная оценка; проверка «пересказа» | `agent/rules.py`, `prompts/analyst.md`, `agent/checks.py` (`retelling`) | `reports/eval.md`: 3,6 признака компании на инсайт, пересечение сути с новостью 0,15 |
| 03 | Аналитика банка и разделение «банк / AI» | Позиция банка только из фрагментов RAG с цитатой и страницей; `kind` у каждого утверждения; атрибуция понижается без источника; расхождение с банком — флаг и пояснение | `agent/assemble.py`, `agent/checks.py` (`attribution`) | карточка: блок «Позиция Альфа-Банка», метки утверждений; тест `test_llm_draft_is_sanitised`; `reports/real_analytics.md` (реальные PDF через OCR) |
| 04 | Связь с первоисточниками, минимум фактических ошибок | Каждое `fact`/`bank_analytics` со ссылкой; ссылки и признаки проверяются; числа только детерминированные; цитата сверяется с текстом | `agent/assemble.py`, ADR-ML-003 | 100% инсайтов проходят валидатор бэкенда (`tests/`, `reports/eval.md`) |
| 05 | Устойчивость на новых новостях | Нет сценариев под конкретные новости: правила по типу события/признакам, LLM-план и аналитик на любом тексте; проверка на профилях реальных клиентов | `agent/plan.py`, `profile.normalize_event`, `eval/real_profiles.py`, `eval/heldout/` | `reports/heldout.md` (новости Интерфакса, не виденные при настройке), `reports/real_profiles.md`; живая лента RSS бэкенда |
| 06 | Полный сценарий до действия | `actions[]`: анализ, мониторинг, менеджер, продукт банка только при связи с задачей | `agent/rules.py` (`_consequences`), `prompts/analyst.md` п.8 | сценарий жюри в корневом README |
| 07 | Масштабирование и сопровождение | Новая отрасль — справочник ОКВЭД бэкенда + шаблон последствий; новый тип клиента — признаки в контексте; новый источник — Tools API; модели и промпты — конфиг и версионируемые файлы | `docs/QUALITY.md` §Сопровождение | — |
| 08 | Метрики и мониторинг с учётом обратной связи | Офлайн-набор и метрики, онлайн-метрики, тревоги, цикл разметки из отзывов | `docs/QUALITY.md`, `eval/` | `GET /v1/info`, `/api/v1/admin/metrics` бэкенда |
| 10 | Уточняющий вопрос, другой разрез, переход к источнику | `/v1/chat`: контекст инсайта, аналитика, новости, группа (разрез по юрлицам), контрагенты; источники в ответе | `alfa_ml/chat.py`, `prompts/chat.md` | тест `test_chat_sse_passes_backend_check` |
| 11 | Агентная логика | План (правила + LLM), выбор инструментов по плану, повторный поиск при пустой аналитике, критик с запросом доп. данных, раунды исправления, откат на rules@1 | `agent/runner.py`, ADR-ML-001 | трассировка инсайта: шаги `plan`, `retrieval`, `retry`, `self_check` |
| 12 | Трассируемость | `log_step` на каждом шаге: план, инструменты, LLM (модель, промпт, токены), проверки, замечания сборщика; `feature_refs` и `relevance.breakdown` в инсайте | `agent/runner.py`, `docs/ARCHITECTURE.md` §Трассировка | `GET /insights/{id}/trace` |
