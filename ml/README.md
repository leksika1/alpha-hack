# ml — ML-сервис «Альфа-Аналитика» (зона команды ML)

Агент, который превращает событие из новостей в персональный инсайт для конкретной компании и роли
пользователя, отвечает на уточняющие вопросы и ранжирует ленту. Работает строго по контрактам
[`../contracts/`](../contracts/README.md): бэкенд вызывает сервис, сервис ходит в Tools API и LLM Gateway бэкенда.

## ml-ranker@2: эмбеддинги + kNN-память разметки + обученная модель (ADR-ML-011, `reports/ranker2.md`)

Логистическая регрессия над признаками правил, 5 семантическими признаками (MiniLM multilingual, fastembed на CPU) и
kNN-памятью разметки (как размечены самые похожие пары «событие × компания»). «Один набор в тест» по 6 размеченным
наборам (демо, Интерфакс ×2, живая лента, РБК, «Коммерсантъ»):

| | ml-ranker@1 | ml-ranker@2 |
|---|---|---|
| nDCG@5, среднее | 0,667 | 0,778 |
| Доля мусора, среднее | 25% | 21% |
| Recall важных / фоновых | 1,0 / 0,71 | 1,0 / 0,64 |

Слепые проверки первой версии: набор №3 (РБК) — мусор 28% → 20% без потери важных; набор №4 («Коммерсантъ») —
мусор 48% → 18%, но пропуск важной пары → kNN-память и новое правило порога (`reports/ranker2_blind_set4.md`).
Слепой набор №5 («Ведомости», поставляемая модель как есть): мусор 39% → 18%, recall важных 0,75 у обеих версий,
фоновых 0,65 → 0,43 (`reports/ranker2_blind_set5.md`). Реранкер (jina v2), признаки по отдельным концептам и бустинг
проверены и отвергнуты абляцией.

## Результаты офлайн-оценки (rules@1, без LLM)

**Демо-лента** (синтетика бэкенда, 5 компаний × 15 событий, `reports/eval.md`):

| | baseline@1 бэкенда | ml-ranker@1 + отбор агента |
|---|---|---|
| nDCG@5 (CFO / CEO) | 0,909 / 0,760 | 0,946 / 0,953 |
| Важные события в ленте (recall gold=2) | 1,00 | 1,00 |
| Доля нерелевантного в ленте (CFO) | 0,51 | 0,20 |

**Отложенный набор** (15 новостей Интерфакса 23–24.10.2026 × 10 реальных клиентов, разметка до прогона,
`reports/heldout.md`): доля нерелевантного 0,355 у baseline → 0,073 у ml-ranker на первом (чистом) прогоне при
том же recall 0,94; найденные на нём общие ошибки (знак курса «рубль вырос», валюта события как связь с ВЭД,
ипотека → застройщики) исправлены, после правок — 0,033 и recall 1,0.

**Живая лента dev-стенда** (331 событие RSS × 5 компаний, `reports/live_feed.md`): до скрининга событий 74% показанного
было нерелевантно, из них 164 карточки с уровнем «высокое/критическое»; после ADR-ML-010 — 41% и 9, все важные
события остаются в ленте. Это честная цифра для «грязного» потока; основные остаточные причины — теги бэкенда.

В офлайн-прогоне `reports/eval.md`: 100% из 65 сгенерированных инсайтов прошли валидатор бэкенда,
100% утверждений имели ссылку на источник, 100% инсайтов — явно помеченные гипотезы.
Это результаты указанного набора без LLM, а не гарантия истинности текста или качества на новом потоке.
На 65 реальных клиентах: медиана 3 события из 15 в ленте, 0 ошибок (`reports/real_profiles.md`).
Реальная аналитика банка (9 PDF-сканов → OCR бэкенда → 203 чанка): позиции банка только из профильных материалов,
цитаты дословные, устаревшие материалы помечаются (`reports/real_analytics.md`).

## Как устроен агент (кратко)

```
plan (правила + LLM-планировщик) → retrieval (контекст компании, событие, аналитика банка, новости,
контрагенты, группа, продукты) → draft (LLM-аналитик или rules@1) → assemble (детерминированная сборка
по контракту) → self_check (правила валидатора бэкенда + качество) → critic (LLM) → revise → final
```

Число раундов исправления задаёт `ML_MAX_ITERATIONS`, по умолчанию — 1; цикл также ограничен оставшимся временем.

- **Классификатор решает, LLM объясняет.** Подверженность компании событию считается детерминированно по
  признакам `company_context` (продукты, ВЭД, отрасль, доли контрагентов, сырьё, регион). Она решает, показывать
  ли событие (`skipped`), даёт оценку влияния (шкала v1) и релевантность (`ml-ranker@2`, при отсутствии
  семантики — `ml-ranker@1`) и задаёт допустимые `feature_refs`. LLM пишет текст и связывает факторы;
  сборщик ограничивает ссылки, признаки и числовые оценки доступными данными. Проверка структуры
  не заменяет проверку смысла и фактической точности объяснения.
- **Сборщик владеет фактами контракта.** Ссылки на несуществующие источники и признаки удаляются, утверждение
  «позиция банка» без фрагмента аналитики понижается до «вывода модели», цитата банка сверяется с текстом
  фрагмента, числа берутся только из детерминированного расчёта.
- **Без LLM сервис работает** (`rules@1`): нет ключа, кончился бюджет (429), провайдер упал, ответ не JSON —
  агент использует правила. Генерация всё равно может завершиться `skipped` или ошибкой инструментов;
  перед публикацией результат проверяет бэкенд.
- **Каждый шаг в трассировке** (`log_step`): план, вызовы инструментов, LLM-вызовы с токенами, результаты
  самопроверки и замечания сборщика, повторы, финал.

## Запуск

В общем стеке: `docker compose up -d --build` из корня — сервис `ml` (порт 8200) является генератором по умолчанию
(`INSIGHT_GENERATOR=remote`, `ML_SERVICE_URL=http://ml:8200`). Вернуться на заглушку: `INSIGHT_GENERATOR=stub`,
`ML_SERVICE_URL=http://ml-stub:8100`.

Локально:

```bash
cd ml
uv sync --frozen
uv run uvicorn alfa_ml.main:app --port 8200
uv run pytest            # тесты: фейковый Tools API/Gateway по contracts/examples + валидатор бэкенда
uv run ruff check alfa_ml tests eval scripts && uv run mypy
uv run python -m eval.run_eval                                   # офлайн-оценка (rules@1)
uv run python -m eval.real_profiles --data-dir ../data/raw       # реальные профили (CSV организаторов)
```

`ML_SERVICE_TOKEN` при интеграции должен совпадать с токеном бэкенда. Остальные настройки имеют значения
по умолчанию: `ML_LLM_ENABLED`, `ML_LLM_PLANNER`,
`ML_LLM_CRITIC`, `ML_MODEL_PLANNER|ANALYST|CRITIC|CHAT` (алиасы из `GET /internal/llm/models`),
`ML_MAX_ITERATIONS` (1), `ML_SKIP_THRESHOLD` (0,35), `ML_LLM_MIN_SCORE` (0,5 — ниже пишет rules@1, экономия бюджета), `ML_LLM_TIMEOUT_S`, `CONTRACTS_DIR`. См. `../.env.example`.

## Модели

| Шаг | Модель по умолчанию | Почему |
|---|---|---|
| Планировщик | Gemma 4 26B A4B | короткий JSON-план, самая дешёвая из списка |
| Аналитик (генерация) | Qwen3.6 35B A3B | хороший русский, JSON, MoE — дёшево |
| Критик | GLM-5.3-Flash | другая модель, чем у аналитика: независимая проверка |
| Чат | Qwen3.6 35B A3B | тот же стиль, что у инсайтов |
| Эмбеддинги (RAG бэкенда) | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (fastembed, 384) | русский, без миграции размерности, без префиксов query/passage |

Адрес провайдера, идентификаторы и ориентировочные тарифы уже заданы в бэкенде; ключ хранится только там.
Выбор моделей проверяется на отдельных прогонах через Gateway, с учётом бюджета (ADR-ML-004).
Проверка настоящей связки без внешней LLM — `make e2e-ml` из корня; подробности —
[`NEXT_STEPS.md`](NEXT_STEPS.md).
